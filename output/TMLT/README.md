## มาตรฐานความปลอดภัย (Clinical Safety & Validation)
การจับคู่ TMLT มีความซับซ้อนกว่า SNOMED เนื่องจากต้องประกอบ 3 แกน ได้แก่ **Component** (สารที่ตรวจ), **Specimen** (สิ่งส่งตรวจ), และ **Method** (วิธีตรวจ) จึงได้ใช้กระบวนการตรวจสอบแบบผสมผสาน (Hybrid Validation):

### สรุปที่มาของข้อมูล (Validation Flags)
เราได้เพิ่มคอลัมน์ `Validation_Flag` เพื่อให้สามารถตรวจสอบย้อนกลับ (Audit Trail) ได้ว่ารหัส TMLT แต่ละบรรทัดนั้นได้มาด้วยวิธีการใด:

1.  **`Auto Corrected (Rule)` (17,470 บรรทัด)**
    *   **ที่มา:** ดึงข้อมูลแล็บที่มีการสั่งบ่อยที่สุด (High-frequency tests เช่น CBC, HbA1c, Lipid Profile, Electrolyte) มาเขียนกฎจับคู่แบบ Manual ทั้ง 3 แกน 
2.  **`Auto Corrected (AI Batch)` (1,619 บรรทัด)**
    *   **ที่มา:** สำหรับรายการแล็บเฉพาะทาง ระบบใช้ AI (LLM) เป็น "ผู้ตรวจทาน (Validator)" โดยประเมินว่ารหัส TMLT ที่ระบบเก่าทำนายไว้นั้น "สมเหตุสมผลทางคลินิกหรือไม่" ถ้ายืนยันว่าถูกต้อง จึงจะให้ผ่านเข้าหมวดนี้
3.  **`Passed Rules` (468 บรรทัด)**
    *   **ที่มา:** ผ่านกฎการจับคู่แบบ Exact Match ของระบบตั้งแต่ขั้นตอนแรกสุด
4.  **`Auto Corrected (Unmapped)` (10,117 บรรทัด)**
    *   **ที่มา:** รายการแล็บที่คลุมเครือ (เช่น "ตรวจแล็บตามโรคที่สงสัย"), หายากเกินไป, หรือ AI ประเมินแล้วว่าระบบเก่าจับคู่มาผิด ระบบจะทำการล้างค่าเป็น `-` ทั้งหมด เพื่อความปลอดภัย (Failsafe) 
5.  **`Auto Corrected (No Data)` (1,943 บรรทัด)**
    *   **ที่มา:** รายการที่รหัสโรค ICD-10 นั้นๆ ไม่มีความจำเป็นต้องเจาะเลือดหรือส่งตรวจแล็บใดๆ 

## คำแนะนำในการนำไปใช้งาน (Implementation Guide)
*   **รหัส TMLT และ LOINC ที่มีค่าเป็น `-`**: หมายความว่าความถี่ในการพบน้อยเกินไป, มีเงื่อนไขกำกวม, หรือไม่มีรหัสมาตรฐานที่ตรงตัว 100% 
*   **ช่อง Method หรือ LOINC ที่มีค่าเป็น `-` (แต่มี TMLT_ID)**: หมายความว่ามาตรฐาน TMLT อนุโลมให้ห้องปฏิบัติการใช้วิธีการตรวจใดก็ได้ (Methodless) โดยยังคงใช้รหัส TMLT ตัวหลักนั้นได้ตามปกติ
*   **คอลัมน์ Audit (AI_Label, Scores)**: ยังคงเก็บรักษาไว้เพื่อเป็น Audit Trail ให้สามารถตรวจสอบย้อนหลังถึงประสิทธิภาพของระบบทำนายผลตัวเก่าได้
